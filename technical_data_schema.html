Key Field Definitions — carried in every SSE event payload and DB record
analysis_id
uuid · generated per upload
UUID generated by the backend the moment a video is uploaded. Identifies one analysis run end-to-end — from upload through to coaching output. Carried in every SSE event so the frontend can match events to the correct upload, even if two uploads happen in the same browser tab.
Generated by
Backend — uuid4() at POST /upload
Relationship
One user_id → many analysis_ids (one per upload)
session_id
uuid · generated client-side at app mount · sessionStorage
A browser-visit identifier generated by the frontend when the app mounts. Identifies one sitting — not the analysis run. A user stays on the same session_id across multiple uploads in one browser tab. Clears when the tab closes. Sent in the POST body and carried in SSE events to support session-level analytics (how many analyses in one sitting). Auth de-scoped — was previously extracted from JWT.
Generated by
Frontend — crypto.randomUUID() at app mount, stored in sessionStorage, sent in POST body
Relationship
One session_id → many analysis_ids (multiple uploads in one browser sitting)
user_id
uuid · device-level anonymous ID · localStorage
A device-level anonymous identifier generated by the frontend on the user's first visit and persisted in localStorage. Identifies the device across multiple sessions and sittings — stable until localStorage is cleared. Used to namespace GCS paths (videos/{user_id}/…) and group analyses for history. Sent in the POST body. Auth de-scoped — was previously a Supabase Auth account ID extracted from JWT.
Generated by
Frontend — crypto.randomUUID() on first visit, persisted in localStorage, sent in POST body
Relationship
One user_id → many session_ids → many analysis_ids
Rule (auth de-scoped): The frontend generates user_id (localStorage) and session_id (sessionStorage) and sends both in the POST body. The backend reads them from the request. analysis_id is still always generated server-side via uuid4() — never passed in by the client.

Python Biomechanics Script ✎ UPDATED
Squad 2 — Backend
About this script
There is no plug-in library for this. This is custom Python code Squad 3 writes in S3-W5-06 (scope) and S2-W6-03 (implement). MediaPipe gives you raw pose landmarks — normalised x/y/z coordinates for 33 body keypoints per frame. This script consumes every frame's keypoints and computes meaningful biomechanics metrics from them.

Core calculation — joint angle:
Given three keypoints A (proximal), B (joint), C (distal), the joint angle at B is:
θ = arccos( dot(BA, BC) / (|BA| × |BC|) )
e.g. knee angle uses hip → knee → ankle keypoints. Hip angle uses shoulder → hip → knee.

What the script produces per rep:
  • Min/max joint angles per joint per rep (from all frames in that rep's time window)
  • Rep segmentation — detects rep boundaries from vertical velocity of hip keypoint
  • Descent / ascent timing in milliseconds
  • Ankle dorsiflexion angle — distance between ankle and toe keypoints projected onto vertical axis
  • Torso lean — angle of shoulder-to-hip vector relative to vertical
  • Tracking confidence — average across all 33 keypoints, count of low-confidence frames

Note: There are community scripts (e.g. on GitHub under mediapipe-pose-angles) that show angle calculation patterns, but they are not exercise-specific. Squad 3 must adapt them for the Goblet Squat joint set, rep segmentation logic, and the specific output JSON schema defined in S3-W5-07.

OpenCV Frame Extraction + Annotation ✎ UPDATED May 21 2026
Squad 3 — Data / Full Stack
V3 updated · May 21, 2026
Why this step exists
Haiku Call 1 outputs per-rep scores. This step detects the camera angle from the biomechanics JSON (camera_angle: 'side' | 'front'), finds the worst-scoring rep, seeks to the correct frame(s), and draws a full annotated overlay: user skeleton (orange), gold standard reference lines (blue), angle arcs, fault/pass label panel, and per-joint plain-English measurements. Runs async after Haiku Call 1 — does not block Tab 1 loading. Side angle: 4 faults annotated on bottom frame. Front angle: 3 faults (knee valgus on ascent frame, trunk shift + hip drop on bottom frame). Updated May 21, 2026 — full annotation overlay scope.
Input
Original video file (GCS URI from form_analyses.video_url) rep_scores[] from Haiku Call 1 output — Squad 2 finds lowest overall score → worst_rep_number bottom_timestamp_ms for that rep — looked up from biomechanics JSON in DB worst_rep angle values from biomechanics JSON (knee, hip, ankle) — for text overlay gold standard angles from Supabase gold standard table — for comparison overlay
Frame Selection Logic V2
1. Find worst rep — from Haiku Call 1 rep_scores[]: worst_rep = min(rep_scores, key=lambda r: r["overall"])
2. Get bottom frame — look up bottom_timestamp_ms for that rep number from biomechanics JSON stored in DB (Step 4)
3. Seek to timestamp — cv2.VideoCapture.set(cv2.CAP_PROP_POS_MSEC, frame.timestamp_ms)
4. Extract raw frame — save to GCS: gs://.../analyses/{analysis_id}/frame_raw.jpg
5. Draw joint overlays — using screen_landmarks from that frame:
  • Green lines (#22c55e) between all tracked joints — cv2.line()
  • Red circles (#ef4444) on joints flagged in error_flags — cv2.circle()
  • Angle labels at flagged joints — cv2.putText()

6. Save annotated frame to GCS: gs://.../analyses/{analysis_id}/frame_bottom.jpg
7. Write URL to DB — UPDATE form_analyses SET annotated_frame_url = '...' WHERE analysis_id = '...'
Output
1 annotated JPEG — worst-rep bottom frame with joint overlays GCS path: gs://kinetic-videos/analyses/{analysis_id}/frame_bottom.jpg URL written to form_analyses.annotated_frame_url

Quality Gate Stage — error_stage: "quality_gate" V2 · May 8, 2026
Fires before any AI processing. Criteria defined in Landmark Quality Framework — Sections 2–3. Three rejection conditions: CRITICAL_OCCLUSION (any critical landmark reliability < 0.60), POOR COMPOSITE (video_score < 0.70), INSUFFICIENT_REPS (complete_reps < 3). M1/M2/M3 carry landmark_medians for left/right message logic. All quality gate failures: retryable = false.
error_code Gate Trigger condition User-facing message retryable
occlusion_left_side M1 CRITICAL_OCCLUSION. ≥1 of knee/hip/heel on left side median_visibility ≤ 0.60. Right side ≥ 0.60. "Part of your left side was hidden from view. Rather than switching sides, rotate your camera slightly toward the front of your body." false
occlusion_right_side M1 CRITICAL_OCCLUSION. ≥1 of knee/hip/heel on right side median_visibility ≤ 0.60. Left side ≥ 0.60. "Part of your right side was hidden from view. Rather than switching sides, rotate your camera slightly toward the front of your body." false
occlusion_both_sides M2 CRITICAL_OCCLUSION. ≥1 of knee/hip/heel median_visibility ≤ 0.60 on both sides. "We couldn't see your lower body clearly. Try angling your camera slightly toward the front so both legs are fully in view." false
out_of_frame_left M3 CRITICAL_OCCLUSION. median_visibility passes but ≥1 of knee/hip/heel on left side median_presence ≤ 0.50. "Your left side kept moving out of frame. Move the camera back slightly so your full body stays visible throughout the squat." false
out_of_frame_right M3 CRITICAL_OCCLUSION. median_visibility passes but ≥1 of knee/hip/heel on right side median_presence ≤ 0.50. "Your right side kept moving out of frame. Move the camera back slightly so your full body stays visible throughout the squat." false
poor_video_quality M4 POOR COMPOSITE. video_score < 0.70. No individual landmark hit 0.60 hard floor. Typical causes: filming from behind, obstruction, low lighting. "We couldn't read your body position clearly. Film from your side with good lighting and a clear background." false
no_reps_detected M5 INSUFFICIENT REPS. complete_reps = 0. A complete rep requires both position_tag "top" AND "bottom" detected in same rep segment. "We couldn't detect any squats in your video. Make sure you're doing goblet squats and your full body is in frame from the start." false
insufficient_reps M6 INSUFFICIENT REPS. 0 < complete_reps < 3. "Film a full set to get your analysis. We need at least 3 complete reps — squat all the way down and all the way back up for each one." false
landmark_medians field: Required in the error event payload for occlusion_left_side, occlusion_right_side, occlusion_both_sides, out_of_frame_left, out_of_frame_right — includes median_visibility and median_presence per critical landmark (knee/hip/heel both sides). Frontend uses these to select the left/right message variant. Not required for poor_video_quality, no_reps_detected, or insufficient_reps.
