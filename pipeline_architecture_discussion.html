Section 2 — Pros and cons
What each option does well and where the risks sit
Option A Biomechanics JSON + Video → Nemotron
Pros
Both inputs ground Nemotron's analysis — JSON confirms what the video shows, reducing hallucinated form issues
Nemotron outputs clean structured JSON → straightforward handoff to Claude, simpler prompt engineering
worst_rep_number is explicit in Nemotron's output — no ambiguity for OpenCV Step 2
Test C (both inputs) is the current plan — test scripts already written and ready to run
Smaller Claude context — Nemotron has already done the analysis, Claude just synthesises coaching
Single analysis_complete SSE event — simpler frontend implementation
Cons
Asking Nemotron to do both visual analysis AND numerical angle comparison — mixing its strengths with reasoning tasks it may not excel at
Gold standard angle comparison ("88° vs ideal 80–95°") is a pure reasoning task — arguably better suited to Claude than a video model
Risk: Nemotron may over-rely on the JSON and under-use its visual capabilities, defeating the purpose of sending the video
If coaching quality is poor, harder to debug — was it the visual analysis or the angle reasoning that failed?
Option B Video only → Nemotron · All reasoning → Claude
Pros
Clean separation — Nemotron does what it's built for (visual movement analysis), Claude does what it's built for (structured data reasoning)
Gold standard angle comparison goes to Claude — a reasoning model comparing numbers is more reliable than a vision model doing the same
All quantitative context (biomechanics, gold standard, weight history) lives in Claude's context together — coherent reasoning in one place
Easier to debug — if visual observations are wrong, it's Nemotron; if coaching or angle reasoning is wrong, it's Claude
Two-phase SSE delivery: user sees coaching text fast, annotated frame loads afterwards — better perceived performance
Cons
Nemotron without the JSON may produce less structured or less reliable output — Test A results are the critical unknown here
Claude receives significantly more context (Nemotron text + biomechanics JSON + gold standard + history + RAG) — larger prompt, higher cost, potential latency impact
worst_rep_number must be derived by Claude from biomechanics data — must be an explicit structured output field, not buried in prose, or OpenCV Step 2 cannot run
Two-phase SSE requires more frontend complexity — two completion events, placeholder state for the image
Unproven — Test A (video only) results needed before committing to this architecture

Key questions to answer from test results
Question 1 — The critical decision gate
Does Nemotron in video-only mode (Test A) return a reliable worst_rep_number and specific per-rep observations — or only qualitative text?
If yes → Option B is viable. If no → Option B loses its clean architecture advantage because Claude still needs to derive worst rep from biomechanics data, making the pipeline more complex with no guaranteed quality gain.
Question 2 — The quality delta
Is Test C output quality meaningfully better than Test A? Or is the video doing most of the work regardless of whether the JSON is also present?
If Test C ≈ Test A in quality → send video only (Option B). If Test C >> Test A → the JSON is grounding the analysis in a meaningful way (Option A). "Meaningfully better" = more specific issue identification, fewer hallucinations, more accurate per-rep scoring.
Question 3 — Context window feasibility for Option B
How long is Nemotron's video-only output in Test A (approximate token count)? Added to biomechanics JSON + gold standard + weight history + RAG docs — does Claude's context stay manageable?
If Nemotron outputs several paragraphs per rep (e.g. 8 reps × 100 tokens = 800+ tokens) plus all other context, total Claude input could approach 8,000–12,000 tokens. Measure this before committing to Option B.
Question 4 — The two-phase SSE trade-off
In Option B, OpenCV Step 2 runs after Claude's output and the annotated frame arrives separately. Does the team want the extra frontend complexity of two-phase delivery, or is a single delivery simpler to ship for demo?
Two-phase is better UX — user sees coaching text faster. But it requires: a second SSE event (frame_ready), a placeholder image state on the Results screen, and keeping the SSE stream open past the coaching completion event. Worth doing but needs a clear frontend task.
Team recommendation — pending test results
Do not commit to either option before running the A/B/C tests. The architecture decision is straightforward once Test A results are in hand — that single test is the deciding factor.

If Test A (video only) produces specific, structured output with per-rep scoring: Go with Option B. Cleaner architecture, Claude does what it's best at, two-phase delivery improves UX.

If Test A produces vague or inconsistent output without the JSON: Stay with Option A. The JSON is doing meaningful grounding work for Nemotron. Shipping a reliable Option A is better than betting on an unproven Option B.

Regardless of option chosen: The two-phase SSE delivery (coaching text first, annotated frame second) is worth implementing — it improves perceived speed and works with either architecture.
Section 4 — Open questions for the team
Bring these to the discussion — answers shape the final decision
1
In Option B, Claude must output worst_rep_number as an explicit structured field — not described in prose — so OpenCV Step 2 can run. Is the team comfortable engineering Claude's prompt to guarantee this field is always present and correctly formatted? What's the fallback if it's missing?
2
In Option A, gold standard angles go into Nemotron. But angle comparison (88° vs 80–95° ideal) is a numerical reasoning task. Do we trust Nemotron to do this reliably, or should gold standard always live with Claude regardless of which option we choose?
3
Two-phase SSE delivery is independent of the Option A/B decision. Should the team implement it regardless — i.e. coaching text always fires first as coaching_complete, then image fires as frame_ready? Or keep a single analysis_complete event for simplicity in the demo?
4
If Option B is chosen and Nemotron's video-only output is verbose (multi-paragraph per rep), how do we handle the Claude context window? Do we summarise Nemotron's output before passing to Claude, or pass the full text? Who writes the summarisation logic?
