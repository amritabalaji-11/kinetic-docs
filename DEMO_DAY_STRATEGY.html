Kinetic Demo Day Strategy

Video Upload Pipeline — What to Build vs. Pre-Compute

Executive Summary

Goal: Show a realistic upload → processing → results flow during the demo, without waiting for the full real-time pipeline.

Approach: Pre-compute all demo results (MediaPipe, Haiku, OpenCV Part 2) + pre-script SSE event sequences. When a demo video is uploaded, the backend recognizes it and replays the pre-recorded event stream with pre-built results.

Benefit: Attendees see a smooth 10–15 second "processing" flow with live progress updates, ending with polished coaching output and annotated form frames.

The Challenge: What, How & Fallback

❓ What We're Trying to Do
Show attendees a realistic upload → processing → results flow. The key: instantly display a polished annotated form frame without waiting for real-time OpenCV processing (which takes 5–10 seconds).

Core insight: The annotated frame is the visual proof. Pre-compute it once per user, reuse it across all their demo uploads.
💡 How We Plan to Do It
1. Pre-compute annotated frame offline (one-time per user):
Select one demo video for each user. Run MediaPipe → identify worst rep → extract frame → annotate with angles → save to GCS.

2. Store in user_profiles table:
Add annotated_frame_url column. Pre-populate for user_001, user_002, user_003 with GCS URLs.

3. Real pipeline runs normally:
User uploads any video → backend processes with real MediaPipe + Haiku. No video hashing, no demo config.

4. Frontend shows pre-computed frame:
Query user_profiles for annotated_frame_url → display if exists. Otherwise, wait for real OpenCV Part 2 result.
📋 Demo Day Execution
You control the upload: You decide which demo video to upload. No attendee surprises.

Setup: Pre-compute annotated frame for your chosen demo video. Store in user_profile for the demo user you're logged in as (e.g., user_001).

During demo: Upload the video you pre-computed for → annotated frame displays instantly from user_profile.

If something goes wrong: You have the pre-computed frame saved in GCS. Can manually display or re-upload same video.
✅ Why This Works
Simplest possible approach. One database column. Real pipeline unchanged. You upload the video you pre-computed for. Annotated frame shows instantly. No video hashing, no config files, no complexity. Same code path for demo and production.

How Videos Are Identified: User Profile Lookup

The Simple Approach

Store the pre-computed annotated frame in the user_profiles table. When demo user uploads a video, immediately show their pre-saved annotated frame.

User logs in as user_001
↓
User uploads video (any video)
↓
Backend queries: SELECT annotated_frame_url FROM user_profiles WHERE user_id = 'user_001'
↓
Show pre-computed annotated image

Why This Works

✓ Zero Video Matching Logic
No hash computation, no DEMO_VIDEOS config, no filename matching. Just a simple database lookup.
✓ One Column Add
Add annotated_frame_url to user_profiles. Pre-populate for demo users. That's it.
✓ No Pipeline Changes
Real MediaPipe, real Haiku, real processing still happens. Annotated frame is just shown from user profile if available.
✓ Production-Ready
After demo, other users won't have annotated_frame_url set, so they get real OpenCV results. Clean handoff.

Decision Point: Full Replay vs. Hybrid Mode

Two approaches to demo mode. Which fits your narrative better?

Option A: Full Replay (Instant)

All results (MediaPipe, Haiku, OpenCV) are pre-computed. Upload video → backend replays event sequence with pre-built results in 10–15 seconds.

Pros:
✓ Guaranteed fast (no real processing)
✓ No code to debug during demo
✓ Full focus on visual output quality
Cons:
✗ Doesn't show real MediaPipe accuracy
✗ If someone asks "what's my score?", it's hardcoded
Option B: Hybrid (Real + Pre-Built)

Run real MediaPipe + Haiku at demo time (~5–8 sec each), but use pre-built OpenCV annotated frame. Results are real, but visual finishes instantly.

Pros:
✓ Real form analysis (actual MediaPipe output)
✓ Can answer "why is the score X?"
✓ Demonstrates real pipeline accuracy
Cons:
✗ Still ~10–15 sec total (real processing time)
✗ More code to test (MediaPipe + Haiku calls)
❓ Team Discussion

Which approach aligns with your demo story? Are you showing "here's what real analysis looks like" (Hybrid), or "here's the polished end-to-end experience" (Full Replay)?

Key Risks

⚠️ Non-Demo Upload
Attendee uploads non-demo video → no pre-built results. Mitigation: Provide demo videos on USB or show friendly error message.
⚠️ SSE Event Timing
Events fire too fast/slow or in wrong order. Mitigation: Test extensively on May 29–30; adjust timing as needed.
⚠️ GCS URL Issues
Pre-built frame URL wrong or corrupted. Mitigation: Verify all URLs 48 hours before demo; keep local backup.
⚠️ Performance Issues
Pipeline still slow (real Haiku call, latency). Mitigation: Use Full Replay mode to guarantee fast demo.
