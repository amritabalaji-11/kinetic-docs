As a demo user entering the app, I want to select which user I am from a simple entry screen, so that the app loads the right session history and progression data for that user — and so the experience feels grounded even without real authentication.

Quality Gate Rejection — contextual error messages
New in v2 — specific re-filming guidance per rejection reason

PT-02 Gold Standard Data Prep — 3–5 Reference Videos
W6New▶
PM + Squad 3 run 3–5 good-form Goblet Squat videos through the MediaPipe + Biomechanics pipeline and store reference values in the DB. This data serves two purposes: grounding Claude's coaching output with real biomechanics reference data, and powering the visual angle overlay on the Results screen.
New product task — W6 data prep · serves 2 purposes
3–5 videos demonstrating correct Goblet Squat form → run through the W6 pipeline → biomechanics JSON stored in gold_standard_biomechanics table.
Purpose 1 — LLM angle reference Gold standard biomechanics data is passed to Claude Sonnet → Claude Haiku 4.5 — Call 2 (async) (W6 A/B test) as reference data for angle comparison — not for coaching language style. Claude uses it to compare the user's measured angles against what good form actually looks like at each joint. e.g. knowing that a gold standard Goblet Squat produces a knee angle of 88° at the bottom, Claude can accurately assess whether 92° is a meaningful deviation or within normal range.
Purpose 2 — Visual overlay (OpenCV Part 2) Gold standard angle ranges are displayed alongside the user's actual angles on the worst-rep annotated frame. e.g. "Knee: 88° · Ideal: 80–95°". Queried from the DB by OpenCV Step 8 at frame extraction time.
Acceptance Criteria
  • 3–5 gold standard videos identified and agreed by PM before end of W6
  • Videos processed through the W6 MediaPipe + Biomechanics pipeline — outputs stored in gold_standard_biomechanics table
  • Reference angle ranges confirmed: knee (80–95° at bottom), hip (80–95°), ankle dorsiflexion (≥25°) — validated against biomechanics research corpus
  • OpenCV Part 2 can query gold_standard_biomechanics to retrieve reference values for overlay (Purpose 2)
  • Gold standard values available in DB for Claude system prompt injection by W7 pipeline build (Purpose 1)

US-08 Form Comparison & Progression Recommendation
W8Updated▶
As a user who has logged multiple sessions, I want to compare my current form against my last session and get a weight progression recommendation, so that I can see whether I'm improving and whether to go heavier.
Architecture change — weight history routing
Weight history (past sessions, weights used, form scores) is retrieved from workout_logs DB table and passed to Claude Sonnet → Claude Haiku 4.5 — Call 2 (async) (W6 A/B test) — not Nemotron. Nemotron analyses the current video only. Claude synthesises the progression recommendation using both Nemotron's output and the historical context.
→ Nemotron = form analysis for this session. Claude = coaching + progression using history. Cleaner separation of responsibilities.
Acceptance Criteria
  • Given I'm on the Results screen, then I see a "Form Comparison" toggle
  • Given I tap the toggle and have a previous session, then I see a side-by-side view: session date + weight, overall form score, parameter breakdown, worst-rep annotated frame, rep-by-rep chart for each session
  • Given I tap the toggle and have no previous session, then I see: "Log more form analyses to see your performance progression"
  • Given multiple sessions exist, the progression recommendation (ready / hold / drop) references specific past sessions by weight

Auth dropped — hardcoded user IDs for demo
2–3 user IDs seeded in the DB (user_001, user_002, user_003). Frontend Upload screen has a simple dropdown to select the demo user. No JWT, no login screen, no session management.
Why: Auth adds significant Squad 1 + Squad 2 effort with zero demo value. The dropdown enables switching demo users to show different progression stories on the dashboard — more compelling than a single user with limited history.
New — v2

5–10 curated coaching documents (PT language, form cues, Goblet Squat references) converted to MD files and injected directly into Claude Sonnet → Claude Haiku 4.5 — Call 2 (async) (W6 A/B test)'s system prompt at Step 9 of the pipeline. No retrieval endpoint, no embeddings, no ingestion pipeline.
Why: 1 exercise + <10 documents = system prompt injection is sufficient. RAG's purpose here is grounding Claude's coaching language, not biomechanics analysis. Vector DB adds significant Squad 3 infrastructure build with no meaningful quality gain at this scale.

v1 — Results Screen
Text coaching ships first, visual overlay follows in W7
Score and text coaching ships in W6. The visual overlay — a still image of the user's worst rep with joint angles annotated — ships in W7.
v2 — what the visual overlay actually is
Already built — OpenCV video overlay (W5, Step 5 of the pipeline) The Squad 3 developer has built a full video overlay: the raw video is processed frame by frame, and green skeleton lines are drawn connecting the joints (hip → knee → ankle), with coloured dots at each joint, angle values displayed on screen (Hip angle, Knee angle, Back angle), rep counter, and movement state detection (STANDING / SQUATTING). This overlay video is what gets sent to Nemotron for AI analysis. It is not shown to the user.
Still to build — still image extraction + annotation (W7, Step 8 of the pipeline) After Nemotron identifies the worst-performing rep, the pipeline seeks to that exact moment in the original raw video and extracts a single still frame. The existing overlay code is then reused to draw on it: skeleton lines, joint position markers colour-coded by status (green = in range, amber = borderline, red = outside range), the user's actual angle values, and a gold standard comparison (e.g. "Knee: 88° · Ideal: 80–95°"). This annotated image is saved and displayed to the user on the Results screen. Estimated 3–4 days to build since the hard work (angle drawing, skeleton, text overlay) is already done from the video overlay step.
