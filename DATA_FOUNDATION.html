Kinetic Data Foundation

Overview

This document defines the core data schemas for exercises, users, and sessions in Kinetic.

  • Database: Supabase (PostgreSQL)
  • Exercise ID Convention: {category}_{sequence}_{exercise_name} (e.g., leg_001_goblet)
  • User ID Strategy: 3 hardcoded user IDs based on profile selection (no UUID generation)
  • Scope: Starting with Goblet Squat (MVP), designed to scale to RDL and beyond

3. Demo User Selection Flow

Frontend (App Launch)

    ├─ "Beginner" card → select
    ├─ "Intermediate" card → select
    └─ "Advanced" card → select
    ↓
User Selects Profile (e.g., "Beginner")
    ↓
Frontend stores: user_id = "user_beginner_001" in sessionStorage
    ↓
ALL subsequent API calls include header: { "user_id": "user_beginner_001" }
    ↓

    ↓

Key point: No dynamic mapping. Each profile card has a hardcoded user_id. Selection is: user picks card → frontend uses that card's ID on every request.

4. Pre-Seeded Session Data (Real User Videos)

Process

Film 2–3 real users performing Goblet Squat. Run each video through the full pipeline (MediaPipe + Haiku Call 1). Save real analysis results to the DB for each user.

Pipeline for Each Real User Video

  1. Record 1 high-quality Goblet Squat video (8–10 reps)
  2. Run through MediaPipe → extract landmarks + quality gate pass
  3. Run through Biomechanics script → calculate angles per rep
  4. Run through OpenCV Part 1 → generate 8-frame composite
  5. Run through Haiku Call 1 → get form scores + coaching + rep breakdown
  6. Run through OpenCV Part 2 → extract worst rep, annotate with angles
  7. Save all outputs to form_analysis_results table
  8. Demo: User selection → Dashboard shows this real analysis
Why Real Data Matters: Real data is infinitely more credible than dummy data. When an investor clicks on a session, they see actual form analysis on an actual person—immediately proves the product works.

5. Biomechanics JSON → OpenCV Frame Extraction Flow

Step 1: Biomechanics Script Output (Squad 3)

{
  "rep_1": {
    "knee_angle": 88.2,
    "hip_angle": 86.5,
    "ankle_dorsiflexion": 22.1,
    "tempo_seconds": 1.37,
    "bottom_frame": 42,
    "bottom_timestamp_ms": 1400
  },
  "rep_2": {
    "knee_angle": 85.0,
    "hip_angle": 87.2,
    "ankle_dorsiflexion": 23.5,
    "tempo_seconds": 1.41,
    "bottom_frame": 84,
    "bottom_timestamp_ms": 2800
  }
}

Step 2: Haiku Call 1 Scoring (Squad 2)

{
  "overall_score": 72,
  "per_rep_scores": [78, 79, 68, 74, 71],
  "worst_rep_index": 2,
  "coaching": "Your ankle dorsiflexion is limiting depth..."
}

Step 3: OpenCV Part 2 Frame Extraction (Squad 3)

The critical handoff: OpenCV reads worst_rep_index → looks up that rep's bottom_timestamp_ms in biomechanics JSON → extracts frame → annotates with angles + gold standard reference lines.

OpenCV Part 2 Logic:
  1. Read worst_rep_index from Haiku output → "2" (rep 3)
  2. Read biomechanics JSON from form_analysis_results
  3. Look up rep_2 (index 2) in JSON → get bottom_timestamp_ms = 2800
  4. Seek raw video to 2800ms
  5. Extract frame at that timestamp
  6. Draw skeleton overlay + angle values
  7. Add gold standard reference lines
  8. Color code: green (in range), amber (borderline), red (out of range)
  9. Save annotated JPEG to GCS
  10. Return annotated_frame_url to frontend via SSE

6. Supabase Table Schemas

Users Table

CREATE TABLE users (
  id TEXT PRIMARY KEY,
  email TEXT UNIQUE NOT NULL,
  name TEXT NOT NULL,
  profile_type TEXT NOT NULL,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

Exercises Table

CREATE TABLE exercises (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  slug TEXT UNIQUE,
  category TEXT,
  difficulty INT,
  description TEXT,
  primary_muscles TEXT[],
  secondary_muscles TEXT[],
  equipment TEXT[],
  created_at TIMESTAMP DEFAULT NOW()
);

User Profiles Table (HOME SCREEN DATA)

CREATE TABLE user_profiles (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id TEXT UNIQUE NOT NULL REFERENCES users(id),
  experience_level TEXT,
  progression_graph_url TEXT,
  calendar_heatmap_url TEXT,
  weight_recommendation TEXT,
  last_progression_status TEXT,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);
For demo: Pre-load progression_graph_url and calendar_heatmap_url pointing to dummy PNG images per user. This is the backup plan if Squad 1 doesn't have time to build real graph logic.

Form Sessions Table

CREATE TABLE form_sessions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id TEXT NOT NULL REFERENCES users(id),
  exercise_id TEXT NOT NULL REFERENCES exercises(id),
  session_date TIMESTAMP,
  weight_value FLOAT,
  weight_unit TEXT,
  created_at TIMESTAMP DEFAULT NOW()
);

Form Analysis Results Table

CREATE TABLE form_analysis_results (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id TEXT NOT NULL REFERENCES users(id),
  exercise_id TEXT NOT NULL REFERENCES exercises(id),
  session_id UUID NOT NULL REFERENCES form_sessions(id),
  weight_value FLOAT,
  weight_unit TEXT,
  biomechanics_json JSONB,
  quality_gate_status TEXT,
  overlay_video_url TEXT,
  annotated_frame_url TEXT,
  haiku_call_1_output JSONB,
  haiku_call_2_output JSONB,
  status TEXT,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

Gold Standard Biomechanics Table

CREATE TABLE gold_standard_biomechanics (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  exercise_id TEXT NOT NULL REFERENCES exercises(id),
  video_url TEXT,
  reference_name TEXT,
  knee_angle_range JSONB,
  hip_angle_range JSONB,
  ankle_dorsiflexion_range JSONB,
  biomechanics_json JSONB,
  created_at TIMESTAMP DEFAULT NOW()
);
