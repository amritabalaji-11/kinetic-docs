As a user who doesn't know how to film themselves properly, I want in-app guidance on how to set up my camera, so that my video produces accurate analysis results.
MVP scope: Lightweight inline component only — Google image or short video showing correct camera angle for Goblet Squat + 3–4 copy tips (distance, height, angle). No custom filming required. No separate modal screen.
Acceptance Criteria
  • Given I'm on the Upload screen, then I see filming tips inline — a Google image/video and 3–4 camera angle tips
  • Given I'm on mobile web, then the tips are readable without zooming
  • Given I dismiss or ignore the tips, then all my upload inputs (exercise, weight, video) remain intact
US-04b Video Submission
W6New▶
As a user ready to analyse my form, I want to select my exercise, enter my weight, and upload a video, so that Kinetic can analyse my session.
Acceptance Criteria

  • Given I've selected an exercise, I can enter the weight I used
  • Given I tap to upload, my device's native file picker opens (photo library + files on mobile)
  • Given I select a video, I see the filename confirmed so I know the right file was chosen
  • Given the file is an unsupported format or too large, I see a clear inline error with guidance
  • Given all fields are complete, the Submit button becomes active
  • Given I tap Submit, I'm taken to the processing screen
US-05 Analysis Processing
W6▶
As a user who just submitted a video, I want to see a clear processing status while Kinetic analyses my footage, so that I know it's working and roughly how long to wait.
Acceptance Criteria
  • Given I've submitted a video, when processing begins, then I see a progress indicator with stage labels (e.g. "Reading your movement patterns…", "Analysing your form…") — not a blank screen
  • Given processing completes, then I'm automatically taken to the Results screen
  • Given processing fails, then I see a clear error message with the option to retry
US-06a Analysis Results — Form Score, 4 Parameters & Rep Progression
W6Split▶
As a gym-goer training alone, I want to see my overall form score, a breakdown across 4 key parameters with coaching, a verdict, and my rep-by-rep progression, so that I immediately understand how I performed and what to prioritise next.
W6: Results screen built against Nemotron output schema using dummy data. Real output wires in W7 (or end of W6 if stretched goal hit).
Overall Form Score
  • Given analysis is complete, I see a consolidated form score /100 prominently at the top of the Results screen
4 Parameter Breakdown — Posture · Stability · Movement Quality · Tempo
  • Given the Results screen, I see 4 parameter sections each showing: score /100 (aggregated across all reps) · 1 affirmation (what I did well) · 1 critical observation · 1–2 actionable coaching tips
  • Parameters are scannable — headline score and affirmation visible first, detail below
Consolidated Verdict
  • Given the Results screen, I see a verdict section with 2–3 bullet points summarising overall performance — a quick-read summary separate from the parameter detail
Rep-by-Rep Progression
  • Given the Results screen, I see a chart showing score per rep across the set — showing whether form improved, held, or degraded
General
  • All content scannable in under 10 seconds — score and verdict first, detail below
  • Mobile web: all sections readable without zooming

US-08 Form Comparison & Progression Recommendation
W8▶
As a user who has logged multiple sessions, I want to compare my current form analysis against my last session, so that I can see whether I'm improving or regressing.
Acceptance Criteria
  • Given I'm on the Results screen, then I see a "Form Comparison" toggle

  • Given my last session is older than 2 months, then I see the same empty state message
  • Given the side-by-side view is active on mobile web, then the two panels are horizontally scrollable or stacked cleanly

US-10 Session History
W7▶
As a user reviewing my progress, I want to see a chronological list of my past sessions, so that I can revisit specific sessions and track how I've progressed.
Acceptance Criteria
  • Given I'm in the History tab, then I see all sessions from the last 6 months in reverse-chronological order — each showing exercise name, date, weight logged, and overall form score

Section 3
Scope Decisions
Decisions made to protect the demo and reduce risk — with plain-language reasoning.
Personalization
Injury input collected but not used in coaching
The app asks about injuries during sign-up and saves the answer to the user's profile. The AI coaching output does not use this information in the MVP.
Why: Too much engineering risk to build, wire, and test injury-personalised coaching in the available time. The injury screen is still shown in the demo — framed as a considered design decision for post-MVP.
Results Screen
Text coaching ships first, visual overlay follows
Score and text coaching ships in Week 6 alongside the first working pipeline. The visual overlay — user's video frame with joints highlighted red/green — follows in Week 7.
Why: The overlay requires both teams to agree on how joint coordinates are passed between backend and frontend. Shipping text first means the results screen isn't blocked while that contract is being agreed.
Demo Day
Narrate the AI pipeline during the processing wait
While the video processes on screen, the presenter talks through what the AI is doing at each stage. If latency is still above 35 seconds by Week 9, a simulated version is built as a planned backup — without replacing the real pipeline.
Why: Turns potential dead air into a product credibility moment. The backup is scheduled work, not a last-minute scramble.
Accuracy Validation
3–5 expert-verified videos for demo day
3–5 expert-verified Goblet Squat videos for demo day. The 20–30 video validation is the bar for beta launch, not for the pitch.
Why: Only one video is shown live on stage. A smaller verified set is honest and achievable for a POC pitch. Claiming 20–30 video validation is not needed at this stage.
Latency Target
Target relaxed from 30s to 35s
The end-to-end pipeline latency target has been updated from under 30 seconds to under 35 seconds.
Why: More realistic for the full pipeline — MediaPipe, Nemotron, RAG retrieval, and Claude Sonnet coaching output in sequence. 35 seconds is still manageable in a live demo with narration.
Progression Logic
Logic defined by PM + PT before engineering builds it
A dedicated product task has been created. The PM and a physical trainer define exactly what "ready to progress", "hold at current weight", and "drop weight" means — with specific thresholds — before the engineering team builds the logic in Week 8.
Why: A wrong recommendation telling a user to go heavier when their form is broken is the highest-severity risk in the product. Without this task, engineering would guess the thresholds.
Workout Builder
Demo if time allows — not demo-critical
Workout Builder is built in Week 8 and shown in the demo only if the core upload → results → comparison flow fits within the 4-minute window. Otherwise shown as a screen on a slide.
Why: Frontend capacity is fully committed to the core demo screens. The Workout Builder adds product depth but the demo story lands without it.
Product Task
PT-01 — Biomechanics & Progression Logic
Two connected jobs: define what to measure (biomechanics parameters) and what to do with the measurement (progression thresholds). Phase 1 is urgent this week.
PT-01 Phase 1 — Biomechanics Parameters & Nemotron Output Schema Owner: PM · This week — W5 ⚠️
Urgency
The engineer cannot finish the biomechanics script until these parameters are defined. Blocks the W6 MediaPipe completion and the first Nemotron call.
Define
Joint parameters for Goblet Squat: which angles to compute (knee, hip, torso lean), at which point in the rep (bottom, mid, top), and which MediaPipe landmark indices to use. Based on research papers and published biomechanics sources — no PT validation needed at this stage.
Also define
Nemotron output schema — agreed between PM and Squad 1 so the Results screen can be built against a known shape:

overall_score: 0–100
rep_scores: [78, 74, 70, ...]
issues: [{ joint, observation }]
coaching_tips: [string]
confidence: "high" | "low"
PT-01 Phase 2 — Refine Against Real Pipeline Output Owner: PM + Squad 2 · Week 7
Week 7
Once the biomechanics script is running and Nemotron is returning real values — check whether the outputs are sensible. Are the angles correct? Is rep count accurate? Are the Nemotron scores reasonable? Adjust parameters and prompt if not. Takes 1–2 hours, not a full sprint.
PT-01 Phase 3 — Progression Recommendation Thresholds Owner: PM + PT Expert 1 · By Mon Week 8
Define
What triggers each recommendation — based on real form scores now visible from Phase 2:
· Ready to progress — score threshold, consistency across sessions, minimum session count
· Hold at current weight — degradation delta between sessions
· Drop weight — which joints, if flagged, always block progression regardless of overall score

This is where PT Expert input matters. Squad 2 cannot build the progression endpoint without this spec.
PT-01 Phase 4 — Expert Validation Owner: PT Experts 1 + 2 · Week 9
Week 9
PT Experts review recommendation outputs on 3–5 test videos. Does "ready to progress" fire when a trainer would agree? Does "drop weight" fire when form is genuinely broken? Flag any mismatches for prompt or threshold refinement.
