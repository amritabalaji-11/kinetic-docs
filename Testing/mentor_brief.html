Model A/B Test — Goblet Squat Form Analysis

Evaluating LLM vision models for biomechanics fault detection + coaching generation

May 2026
2 testers (Amrita + Ezequiel)
6 videos · 9 variants · 54 API calls
Objective

Determine which AI model (or combination) can reliably detect goblet squat form faults from video + biomechanics data, and generate coaching feedback good enough for a fitness product.

Core question: Does adding visual input (frames or full video) improve fault detection over JSON-only analysis?

How We Defined Success
  • Form accuracy: ≥ 4/6 videos correctly classified (fault or no fault) — minimum bar
  • 6/6 = viable for production consideration
  • Latency: < 30s for post-session review
  • Cost: < $0.05/call to maintain margin at $15/month
  • Coaching quality: PT-rated 1–5 on specificity, accuracy, actionability
Inputs Used
  • 6 standardised videos — 3 fault types × fault + good form pair
  • Depth fault/good (side view)
  • Knee valgus fault/good (front view)
  • Torso lean fault/good (side view)
  • MediaPipe JSON — joint angles, rep metrics, trends per rep
  • Processed video — 10fps with skeleton overlay from MediaPipe pipeline

Key Findings
  • Visual input helps — Gemini D (skeleton overlay) scored 6/6 vs 5/6 for Gemini B (raw video). The pre-drawn skeleton reduced visual ambiguity.
  • GPT-4o mini ignores visual input — source was json on every call despite receiving frames. Accurate but not using the visual channel.
  • NVIDIA models are not viable — too slow (40–290s), API reliability issues, 1-image-per-request limit on 90B Vision model.
  • Claude Sonnet produced the best coaching — spotted bilateral foot asymmetry (17° gap), cited per-rep trends (+0.9°/rep), and chained ankle → lean → depth as one problem vs three separate issues.
  • All 3 winners (D, H, J) are affordable — even Sonnet at $0.033/call = $0.26/user/month at 8 analyses/month on a $15 subscription.
Interesting Tensions Found
  • V4 false positive — every model falsely flagged good-form knee tracking as valgus. Root cause: the pipeline's valgus_flag fires on 2/5 reps at borderline distance. Fixed by switching to a 50% majority rule on raw knee distance < 0.22.
  • Latency vs quality tradeoff — Haiku is 2.5× faster than Sonnet (12s vs 30s) with same accuracy. Coaching depth is meaningfully different — Sonnet more clinical and root-cause driven.
  • Skeleton overlay helps Gemini, not GPT-4o mini — Gemini D > B (6/6 vs 5/6). GPT F = G (5/6 both). Suggests GPT isn't processing the visual at all.
  • Dorsiflexion always flagged as restricted — pipeline stores string label not numeric degrees. Fixed: now outputs both dorsiflexion_at_bottom_deg and classification.
Prompt Improvements Made During Test
  • Added rep counting to all observations ("4 of 5 reps", not just "you have lean")
  • Added trend detection using JSON trend fields (+0.9°/rep worsening)
  • Added bilateral asymmetry check — flag foot turnout gap > 10°
  • Added causal chain requirement — ankle → lean → depth as one problem, not three
  • Added walk-in/walk-out rule — reps with 3× median duration excluded from feedback
  • Added source tagging — did each fault observation come from JSON, visual, or both?
  • Added verdict field — 2-3 sentence action-oriented summary shown to user first
Next Test — Already Running

Question: Can we get Sonnet-quality coaching at lower cost by splitting the pipeline?

  • Option 1: Sonnet end-to-end (baseline) — $0.033/call, ~33s
  • Option 2: Gemini analyses → Sonnet coaches — $0.007/call, ~47s
  • Option 3: Haiku analyses → Sonnet coaches — $0.017/call, ~36s

Early result: All 3 scored 6/6. Option 2 wins — 5× cheaper than Option 1, same coaching quality. Sonnet coaching is the bottleneck for both cost and latency regardless of which model analyses first.
