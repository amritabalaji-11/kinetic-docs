Landmark Quality Framework

MediaPipe → Biomechanics Data Contract · Goblet Squat MVP
Squad 3 · implements Squad 2 · consumes Ref: S3-W5-06 · S3-W5-07
ℹ This document defines the quality gate that S3-W5-06 (MediaPipe processing) applies before passing frame data to S3-W5-07 (biomechanics computation). Both tasks should be read alongside this spec. The landmark weights and score thresholds here are starting values — update this doc when tuned against real video data.
Why All Eligible Frames — Design Rationale
Read this before implementing. It explains the core design decision that shapes everything in this document.
Biomechanics computation needs trajectory data, not snapshots.
To compute metrics like range of motion, knee angle progression through a rep, depth reached, or whether the descent was controlled — biomechanics must see how values change over time. A single frame at the bottom position tells you the angle at that moment. The full trajectory of frames tells you how the person got there, how fast, and whether the pattern is consistent across reps. Top and bottom frames are selected for the LLM (coaching), not for biomechanics.
What biomechanics receives
  • ✓ All reliable frames within each rep — full trajectory
  • ✓ World landmarks (3D metric, hip-centred) — better for angle math than normalised screen coords
  • ✓ Raw visibility + presence scores on every landmark in every eligible frame
  • ✓ Frame index + timestamp_ms on every frame
  • ✓ Landmarks with no form impact excluded — not all 33
What biomechanics does NOT receive
  • ✗ Key frames only (top / bottom / error frames) — those are for the LLM, not biomechanics
  • ✗ All 33 landmarks — no-impact landmarks (mouth, wrist, fingers, eye inner/outer) are stripped before passing
  • ✗ Frames outside rep segments — setup and rest frames are excluded
  • ✗ Frames where any critical landmark fails visibility ≥ 0.70 — unreliable frames are filtered out before passing
Why pass raw visibility scores — not just pre-filtered frames
Pre-filtering removes frames where critical landmarks fail entirely (≥ 0.70 gate). But among frames that pass, reliability still varies — a frame where the left knee scores 0.72 should carry less weight in angle calculations than a frame where it scores 0.95. Passing the raw scores lets biomechanics computation weight frames by confidence rather than treating all eligible frames as equally trustworthy. The filtering gate keeps noise out; the scores let the downstream logic be precise about uncertainty.

2   Visibility Scoring Framework
A three-layer quality gate. All three layers run before any frame data is passed to biomechanics.
Layer 1 — Per-Landmark Reliability Rate
# For each tracked landmark across all frames in the video:
reliability(lm)  =  count(frames where visibility(lm) ≥ 0.70 AND presence(lm) ≥ 0.70)
                 ÷  total_frames

# Output: one score per landmark, range 0 → 1
# e.g. left_knee: 0.88 means reliable in 88% of frames
MediaPipe provides both visibility (occlusion probability 0–1) and presence (in-frame probability 0–1) as separate scores. Both must pass — a landmark can be in-frame but occluded.
Layer 2 — Weighted Composite Video Score
Critical 50%
Important 35%
Least Impact 15%
# Weight allocation — sums to 1.0
Critical    (6 landmarks):  0.50 ÷ 6 = 0.083 per landmark
Important  (8 landmarks):  0.35 ÷ 8 = 0.044 per landmark
Least Impact (5 landmarks):  0.15 ÷ 5 = 0.030 per landmark

# Composite score
video_score = Σ weight(lm) × reliability(lm)  for all tracked landmarks

# Output: 0 → 1 (e.g. 0.82 = Acceptable)
Layer 3 — Hard Floor Rule (Critical Landmarks)
The composite score can mask a catastrophic failure. A single critical landmark with 40% reliability makes biomechanics for that joint unreliable — even if the overall score looks fine.
# Applied per critical landmark, independent of composite score
for lm in [left_hip, right_hip, left_knee, right_knee, left_heel, right_heel]:
  if reliability(lm) < 0.60:
    flag = CRITICAL_OCCLUSION
    reason = f"{lm} visible in only {reliability(lm)*100:.0f}% of frames"
    → reject video or surface warning before biomechanics runs
⚠ The 0.60 hard floor is a starting value. Tune upward once real video data is available — if knees are reliably visible in fewer than 60% of frames, biomechanics output will be noisy regardless of the composite score.
Score Thresholds
Composite Score Status Action Typical cause
≥ 0.85 GOOD Proceed with full analysis, no flags Good camera angle, unobstructed view
0.70 – 0.84 ACCEPTABLE Compute biomechanics; flag output as lower confidence Baggy clothing, slight angle issues, background clutter
< 0.70 POOR Warn user — camera setup or occlusion issue likely Filming from behind, heavy obstruction, poor lighting
3   Frame Selection Criteria for Biomechanics
Four sequential gates. A frame must pass all applicable gates to be included in the biomechanics payload. Applied per-rep, not globally.
1
Reliability Gate — per-frame check on critical landmarks
Every critical landmark must pass the visibility + presence threshold in this specific frame. A frame where the left knee dips to 0.62 visibility is excluded from biomechanics — even if it was reliable in most other frames.
# Per frame — check all critical landmarks
frame_reliable = all(
  lm.visibility ≥ 0.70 and lm.presence ≥ 0.70
  for lm in critical_landmarks(frame)
)
# If False → exclude frame entirely, do not pass to biomechanics
2
Rep Membership — frame must belong to an active rep segment
Frames outside rep segments — setup, rest between reps, end of video — are excluded. Rep segment boundaries are provided by the rep segmentation logic in S3-W5-07. Each passing frame is tagged with its rep_index.
# rep_segments: list of (start_frame, end_frame) per rep — from S3-W5-07
rep_index = find_rep(frame_index, rep_segments)
if rep_index is None:
  # Frame is between reps or outside rep window → exclude
  skip frame
3
Key Position Tagging — top and bottom position frames per rep
Within each rep, identify the frame at the top position (standing, hip at highest world y) and the frame at the bottom position (maximum squat depth, hip at lowest world y). These frames are tagged and apply a higher reliability bar (≥ 0.85) across both critical and important landmarks — because they are the primary frames sent to the LLM for coaching analysis.
# Using world landmarks — metric coordinates, hip-centred
top_frame   = frame with min(avg(left_hip.y, right_hip.y)) within rep
bottom_frame = frame with max(avg(left_hip.y, right_hip.y)) within rep

# Higher reliability gate for key position frames
key_frame_reliable = all(
  lm.visibility ≥ 0.85 and lm.presence ≥ 0.85
  for lm in critical_landmarks(frame) + important_landmarks(frame)
)
# Tag: position_tag = "top" | "bottom" | None
4
Payload Construction — what gets sent per frame
Only critical + important landmarks are included in the biomechanics payload. Least-impact landmarks are available optionally. No-impact landmarks are never passed. World coordinates are the primary coordinate system; normalised x/y are included for screen-space checks (e.g. knee tracking relative to toe position).
{
  "frame_index": 142,
  "timestamp_ms": 4733,
  "rep_index": 2,
  "position_tag": "bottom",  // "top" | "bottom" | null — set by S3-W5-06
  // error_flags and error_values are NOT in this payload —
  // Points of Max Error are identified by S3-W5-07 after biomechanics computation (see Section 4)
  "frame_reliability": 0.91,  // lowest visibility score among critical landmarks this frame
  "world_landmarks": {  // 3D metric coords, origin at hip midpoint — primary for angle math
    "left_hip": { "x": -0.08, "y": 0.21, "z": 0.01, "visibility": 0.94, "presence": 0.96 },
    "right_hip": { "x": 0.07, "y": 0.20, "z": 0.00, "visibility": 0.93, "presence": 0.95 },
    "left_knee": { "x": -0.11, "y": 0.48, "z": 0.03, "visibility": 0.91, "presence": 0.92 },
    // ... all critical + important landmarks
  },
  "screen_landmarks": {  // normalised x/y (0–1) for screen-space checks only
    "left_knee": { "x": 0.41, "y": 0.63 },
    "left_foot_index": { "x": 0.39, "y": 0.88 },
    // ... critical + important landmarks
  }
}
4   Points of Max Error — implemented by S3-W5-07 after biomechanics computation
These frames are identified after S3-W5-07 has run the angle computations — not at the MediaPipe stage. They use the same biomechanics math that S3-W5-07 already computes, so there is no duplication. S3-W5-07 annotates the relevant frames with error_flags and error_values and passes the annotated frames to the LLM stage.
⚠ Error frame detection requires rep segmentation boundaries and computed joint angles — both of which are S3-W5-07 outputs. Attempting to detect these in S3-W5-06 would require running the same angle math twice. Do not implement Points of Max Error in S3-W5-06.
A Max Depth Error — "Half-Squat" error_flag: depth_insufficient
When: Computed at the bottom frame only (tagged by S3-W5-06). Landmark basis: Hip (23/24), Knee (25/26), Ankle (27/28) — world coordinates. Research threshold: Schoenfeld (2010) — parallel depth is reached when the hip crease is below the knee. Knee angle > 100° at bottom = insufficient depth.
# Knee angle = angle at the knee joint — S3-W5-07 computes this as part of standard biomechanics
hip_vec   = hip_midpoint  − knee_midpoint   # vector from knee toward hip
ankle_vec = ankle_midpoint − knee_midpoint   # vector from knee toward ankle

cos_angle = dot(hip_vec, ankle_vec) / (|hip_vec| × |ankle_vec|)
knee_angle_deg = degrees(arccos(cos_angle))

# Applied at the frame tagged position_tag="bottom" by S3-W5-06
if knee_angle_deg > 100:
  bottom_frame["error_flags"].append("depth_insufficient")
  bottom_frame["error_values"]["knee_angle_at_depth"] = knee_angle_deg
B Max Knee Valgus — "Knee Cave" error_flag: max_knee_valgus
When: First 10–20% of the concentric phase (start of the ascent from bottom). Load is heaviest here — where valgus collapse most commonly occurs. Why S3-W5-07: Concentric phase boundary detection is part of rep segmentation, which S3-W5-07 owns. Landmark basis: Left Knee (25) and Right Knee (26) — screen x coordinates (normalised). Screen x is correct here: valgus is a lateral collapse visible in the camera plane, not a depth change.
# concentric_start comes from S3-W5-07 rep segmentation — not available in S3-W5-06
concentric_start = frame after bottom_frame where hip_y begins decreasing
concentric_window_end = concentric_start + 0.20 × (top_frame − bottom_frame)

# Minimum inter-knee x-distance within the concentric window
knee_x_dist(frame) = abs(left_knee.screen_x − right_knee.screen_x)

valgus_frame = argmin(knee_x_dist, frames[concentric_start : concentric_window_end])
valgus_frame["error_flags"].append("max_knee_valgus")
valgus_frame["error_values"]["knee_x_distance"] = knee_x_dist(valgus_frame)
C Max Butt Wink — Posterior Pelvic Tilt error_flag: butt_wink
When: Deepest point of the squat (near or at bottom frame). Why S3-W5-07: Torso–pelvis angle is the same calculation as torso lean — already a standard biomechanics metric. Landmark basis: Shoulder midpoint (11/12), Hip midpoint (23/24), Knee midpoint (25/26) — world coordinates. MediaPipe has no spine landmarks; torso–pelvis angle is the best available proxy for lumbar flexion.
# Both vectors already computed by S3-W5-07 biomechanics — no extra work
torso_vec(frame)  = hip_midpoint  − shoulder_midpoint
pelvis_vec(frame) = knee_midpoint − hip_midpoint

torso_pelvis_angle(frame) = degrees(arccos(
  dot(torso_vec, pelvis_vec) / (|torso_vec| × |pelvis_vec|)
))

# Baseline at top_frame (standing) — already computed for top position
baseline_angle = torso_pelvis_angle(top_frame)

# Search ±10 frames around bottom for maximum deviation
wink_frame = argmax(torso_pelvis_angle(f) − baseline_angle, frames near bottom)

if (torso_pelvis_angle(wink_frame) − baseline_angle) > 15:
  wink_frame["error_flags"].append("butt_wink")
  wink_frame["error_values"]["pelvic_deviation_deg"] = deviation
Proxy limitation: Captures relative torso–pelvis rotation, not lumbar curvature directly. Accurate butt wink detection would require sacrum/L5 landmarks. Flag this when testing against real video data.
