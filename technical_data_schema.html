Python Biomechanics Script
Squad 2 — Backend
About this script
There is no plug-in library for this. This is custom Python code Squad 3 writes in S3-W5-06 (scope) and S2-W6-03 (implement). MediaPipe gives you raw pose landmarks — normalised x/y/z coordinates for 33 body keypoints per frame. This script consumes every frame's keypoints and computes meaningful biomechanics metrics from them.

Core calculation — joint angle:
Given three keypoints A (proximal), B (joint), C (distal), the joint angle at B is:
θ = arccos( dot(BA, BC) / (|BA| × |BC|) )
e.g. knee angle uses hip → knee → ankle keypoints. Hip angle uses shoulder → hip → knee.

What the script produces per rep:
  • Min/max joint angles per joint per rep (from all frames in that rep's time window)
  • Rep segmentation — detects rep boundaries from vertical velocity of hip keypoint
  • Descent / ascent timing in milliseconds
  • Ankle dorsiflexion angle — distance between ankle and toe keypoints projected onto vertical axis
  • Torso lean — angle of shoulder-to-hip vector relative to vertical
  • Tracking confidence — average across all 33 keypoints, count of low-confidence frames

Note: There are community scripts (e.g. on GitHub under mediapipe-pose-angles) that show angle calculation patterns, but they are not exercise-specific. Squad 3 must adapt them for the Goblet Squat joint set, rep segmentation logic, and the specific output JSON schema defined in S3-W5-07.

OpenCV Frame Extraction + Annotation
Squad 2 — Backend
Why this step exists
Nemotron identifies when form issues occur — it outputs timestamps in milliseconds (e.g. first_detected_ms: 8400). But Nemotron does not produce images. This step converts those timestamps into actual video frames the user can see.

Without frame extraction, the analysis is purely text and numbers — "your left knee collapsed on reps 3–8." With it, the user sees a frozen frame at the exact moment of failure, with angle arcs, joint highlights, and arrows drawn on it. This is what makes the coaching believable and actionable for a non-expert user — it's the X-ray that proves the diagnosis.
Input — from Nemotron output
Issue timestamps (ms) from Nemotron form_issues[].key_frames[] Original video file (GCS URI from form_analyses.video_url)
Process
1. Seek to timestamp — OpenCV opens the video file from GCS and seeks to each timestamp_ms in Nemotron's output using cv2.VideoCapture.set(cv2.CAP_PROP_POS_MSEC, timestamp)
2. Extract raw frame — reads the JPEG at that position, saves raw frame to GCS: /frames/raw/f_001.jpg
3. Draw annotations — using cv2.ellipse(), cv2.arrowedLine(), cv2.circle() — draws the overlay_annotations defined in Nemotron output (angle_arc, arrow, joint_highlight) in the specified colour (#ef4444 for issues, #22c55e for good)
4. Write annotated frame — saves to GCS: /frames/annotated/f_001.jpg
5. Repeat for every key frame across all detected issues (typically 8–15 frames per session)
Output
Raw frame URLs — gs://kinetic-videos/videos/{user_id}/{analysis_id}/frames/raw/ Annotated frame URLs — gs://kinetic-videos/videos/{user_id}/{analysis_id}/frames/annotated/

Error Taxonomy — error_code Reference
Frontend reads error_code from the error SSE event to select the right message + CTA. retryable: "true" = same video is fine, infrastructure failed. retryable: "false" = the video itself needs to change. retryable: "partial" = pipeline continues with degraded output.
